# 03. 메모리 — 세션을 넘어 기억하기

## 문제

Claude Code 세션은 기본적으로 휘발성입니다. 창을 닫으면 "나는 한국어를 쓰고, Windows 환경이고, 이 결정은 이미 내렸다"는 맥락이 사라집니다. 매번 다시 설명하는 건 낭비입니다.

## 해법: 파일 기반 영속 메모리

한 가지 사실 = 한 개 파일. 프론트매터로 분류하고, `MEMORY.md` 인덱스 한 줄로 묶습니다.

- 위치: `~/.claude/projects/<인코딩된-cwd>/memory/`
- 인덱스: `memory/MEMORY.md` — 매 세션 자동 로드되는 목차(한 줄 요약)
- 각 사실: `memory/<slug>.md` — 본문 1개 사실

### 파일 형식

```markdown
---
name: <짧은-kebab-슬러그>
description: <한 줄 요약 — 관련성 판단에 쓰임>
metadata:
  type: user | feedback | project | reference
---

<사실 본문. feedback/project는 **Why:** / **How to apply:** 줄 권장.
 [[다른-메모리-name]] 으로 연결.>
```

### 분류(type) 4가지

| type | 무엇 | 예시 |
|---|---|---|
| `user` | 사용자가 누구인지 (역할·전문성·취향) | "컴퓨터 비전 배경, 한국어 선호" |
| `feedback` | 작업 방식에 대한 지침(교정·확인된 접근) | "삭제 전 항상 확인받기 — 왜/어떻게 적용" |
| `project` | 코드/깃 이력에서 안 드러나는 진행 맥락 | "이 기능은 X 때문에 보류 중" |
| `reference` | 외부 리소스 포인터 | "대시보드 URL, 티켓 번호" |

---

## 왜 이 구조가 좋은가

1. **인덱스만 항상 로드** — 전체 메모리를 매번 통째로 불러오면 컨텍스트 낭비. `MEMORY.md` 한 줄 요약만 항상 로드하고, 필요할 때 해당 파일을 펼칩니다.
2. **한 파일 = 한 사실** — 갱신·삭제가 외과적. 틀린 사실은 그 파일만 지우면 됩니다.
3. **연결(`[[name]]`)** — 관련 사실끼리 위키처럼 링크. 아직 없는 메모리를 가리켜도 OK(나중에 쓸 거리 표시).
4. **타이밍** — 사용자가 같은 걸 정정하거나 반복할 때가 메모리화 최적 시점.

## 무엇을 저장하면 안 되나

- 코드 구조·과거 수정·깃 이력·CLAUDE.md에 이미 있는 것 → 저장 금지(중복)
- 이번 대화에서만 의미 있는 것 → 저장 금지
- "이거 기억해"라고 했는데 위에 해당하면 → "무엇이 비자명했는지"를 물어 그걸 저장

---

## 자동 정리

메모리는 시간이 지나면 중복·모순·진부화가 쌓입니다. `consolidate-memory` 스킬 + 월 1회 자동 루틴([04-automation.md](04-automation.md))으로 정리합니다:

- 중복 병합, 모순 해소, 낡은 사실 제거
- `MEMORY.md` 인덱스 정합성 점검

## 예시 인덱스

```markdown
# Memory Index

## User
- [사용자 프로필](user_profile.md) — 역할·배경·선호 한 줄

## Project
- [프로젝트 A](project_a.md) — 목표·제약·현재 상태 한 줄

## Feedback
- [자율 운영 원칙](feedback_autonomous.md) — 직접 적용 후 보고, 비가역은 확인

## Reference
- [백업 인프라](reference_backup.md) — 매주 금 자동 백업, 8주 보관
```
